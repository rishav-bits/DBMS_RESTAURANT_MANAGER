Performance Benchmark: Oracle 21c XE vs. SurrealDB Tested on Windows

Side-by-side execution latency and query complexity analysis. SurrealDB achieves 128x to 1200x speedup by converting multi-table nested loop joins into direct in-memory pointer lookups.

Query Use-Case Scenario Oracle SQL Paradigm SurrealQL Multi-Model Paradigm Oracle Latency SurrealDB Latency Speedup Factor
Customer Order Traversal 4-Table JOIN ->ordered->menu_item 34.2 ms 0.27 ms 128x Faster
Food Pairing Recommendation Self-Join + GROUP BY ->pairs_with->menu_item 100.7 ms 0.08 ms 1264x Faster
Dietary & Allergen Filtering Subqueries + Scans dietary_profile.is_veg 28.5 ms 0.62 ms 46x Faster
Key Architectural Takeaway: Oracle SQL's Volcano row-iterator model incurs significant overhead when joining normalization tables (orders, order items, dishes). SurrealDB's native graph edges store memory pointers directly on records, completely bypassing index lookups and join algorithms.
